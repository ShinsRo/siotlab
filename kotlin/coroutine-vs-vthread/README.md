# Coroutine vs Virtual Thread

코루틴과 가상 스레드를 비교할 때는 단순히 "더 빠른가"만 보면 부족하다. 이 문서는 두 모델을 어떤 기준으로 비교하면 좋은지 정리한 출발점이다.

코루틴과 가상 스레드는 모두 높은 동시성을 다루기 위한 도구이지만, 추구하는 모델이 다르다.

- 코루틴: 적은 비용의 비동기 태스크와 구조화된 동시성에 강점이 있다.
- 가상 스레드: 동기식 코드 스타일을 유지하면서 대규모 동시성을 처리하는 데 강점이 있다.

## 실험 시나리오

### 1. I/O Bound

- 1-1. `sleep` 기반 synthetic benchmark
- 1-2. HTTP 클라이언트 호출

확인할 것:

- 처리량
- 평균 응답 시간
- p95, p99 지연시간

### 2. Massive Fan-out / Fan-in

- 작은 작업 수천~수만 개 생성 후 결과 수집

확인할 것:

- 작업 생성 비용
- 합류(join) 비용

## 비교 시 주의할 점

- 같은 워크로드를 사용해야 한다.
- 같은 JVM 버전, 같은 머신, 같은 힙 설정을 사용해야 한다.
- 워밍업과 측정을 분리해야 한다.
- 평균값만 보지 말고 p95, p99를 함께 봐야 한다.
- synthetic benchmark와 실제 애플리케이션 시나리오를 구분해야 한다.

## 해석 가이드

- 코루틴이 유리한 경우
  - 구조화된 동시성이 중요할 때
  - 취소와 timeout 제어가 핵심일 때
  - fan-out/fan-in 패턴이 많을 때
- 가상 스레드가 유리한 경우
  - 기존 blocking 코드와 라이브러리를 많이 재사용해야 할 때
  - thread-per-request 모델을 단순하게 확장하고 싶을 때
  - Java 생태계와의 자연스러운 통합이 중요할 때

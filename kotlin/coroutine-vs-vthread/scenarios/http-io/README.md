# HTTP I/O

외부 HTTP 서버를 대상으로 코루틴과 가상 스레드의 I/O 처리 특성을 비교한다.

테스트 대상 서버는 Testcontainers로 기동한 MockServer다.

이 시나리오에서 코루틴은 비동기 메커니즘인 `HttpClient.sendAsync(...).await()`를 사용하고, 가상 스레드는 동기 메커니즘인 `HttpClient.send(...)`를 사용한다.

## 결과

| 구현 | 요청 수 | 지연(ms) | 총 수행 시간(ms) | 최대 동시 요청 수 | req/s | 평균 지연 | p95 | p99 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| coroutine | 1000 | 200 | 3600 | 1000 | 277.78 | 2886.04 | 3530 | 3540 |
| virtualThread | 1000 | 200 | 744 | 1000 | 1344.09 | 587.91 | 724 | 738 |
| coroutine | 1000 | 500 | 1750 | 1000 | 571.43 | 1499.64 | 1672 | 1690 |
| virtualThread | 1000 | 500 | 1051 | 1000 | 951.47 | 807.79 | 1039 | 1043 |
| coroutine | 1000 | 1000 | 1364 | 1000 | 733.14 | 1252.57 | 1308 | 1322 |
| virtualThread | 1000 | 1000 | 1375 | 1000 | 727.27 | 1318.00 | 1359 | 1366 |

## 해석

- `serverDelayMillis=200`, `500` 구간에서는 `virtualThread`가 더 짧은 총 수행 시간과 더 높은 처리량을 보였다.
- `serverDelayMillis=1000`에서는 두 구현의 총 수행 시간이 거의 비슷하다. 지연 시간이 충분히 길어지면 클라이언트 측 오버헤드보다 서버 대기 시간이 더 크게 작용한다.
- `200ms`, `500ms` 구간에서 코루틴의 `평균 지연`, `p95`, `p99`가 더 크게 나왔다. 현재 구현에서는 `sendAsync(...).await()` 경로의 관리 비용이 높은 요청 수에서 더 크게 드러난 것으로 볼 수 있다.
- `최대 동시 요청 수`는 모든 케이스에서 `1000`에 도달했다. 현재 구현 기준으로는 두 모델 모두 요청 수만큼 동시 요청을 한 번에 밀어넣는 형태를 유지했다.
- 이번 결과는 높은 동시성을 인위적으로 제한하지 않은 상태에서, 짧거나 중간 길이의 HTTP 대기에서는 가상 스레드가 더 유리하고, 매우 긴 대기에서는 차이가 줄어드는 패턴을 보여준다.

## 주의

- 이 결과는 MockServer를 대상으로 한 synthetic HTTP workload 결과다.
- 코루틴은 `HttpClient.sendAsync(...).await()`, 가상 스레드는 `HttpClient.send(...)`를 사용했다. 즉 같은 HTTP 작업을 각 모델의 자연스러운 방식으로 수행한 비교다.
- 따라서 이 표만으로 실제 서비스 환경 전체에서 가상 스레드가 항상 더 빠르다고 결론 내리면 안 된다.

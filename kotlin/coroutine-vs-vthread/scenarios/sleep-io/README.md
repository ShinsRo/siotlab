# Sleep I/O

## 테스트 목적

- 대기성 작업 수가 많아질 때 어느 모델이 더 적은 오버헤드로 동시성을 유지하는가
- 작업 수가 증가할 때 전체 완료 시간이 어떻게 변하는가
- 같은 조건에서 메모리 사용량과 스케줄링 비용이 어떻게 달라지는가

## 작업 규칙

- 모든 작업은 같은 대기 시간을 가진다.
- 모든 작업은 같은 시점 또는 같은 조건에서 시작한다.
- 각 작업은 대기 후 동일한 형태로 종료된다.

## 초기 파라미터

- 작업 수: `1_000`, `10_000`, `100_000`
- 대기 시간: `1ms`, `10ms`, `50ms`
- 반복 횟수: 워밍업과 측정을 분리한 고정 횟수

## 초기 측정 지표

- 전체 완료 시간
- 처리량
- 메모리 사용량
- p95, p99 지연시간

## 구현 대응

- 코루틴: non-blocking 대기 사용
- 가상 스레드: blocking 대기 사용

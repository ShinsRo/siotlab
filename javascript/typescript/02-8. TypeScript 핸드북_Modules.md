# Modules

- JS 는 오랜 세월 여러 모듈 시스템 (AMD, CommonJS, UMD, SystemJS, ESM 등) 을 거쳐옴
- ES6 이후 ES Modules (`import` / `export`) 가 표준
- TS 는 이 모든 것을 지원함

## JS 에서 모듈은 어떻게 정의되는가

- TS 도 ECMAScript 2015 와 같은 규칙을 따름
- **`import` 또는 `export` 를 top-level 로 갖는 파일은 모듈**
- 아무것도 없으면 그 파일의 선언들은 **글로벌 스코프** 에 있음
- 모듈은 자신만의 스코프를 가짐 → 다른 모듈에서 사용하려면 명시적으로 export/import

## non-modules

- 모듈이 아닌 파일 (script) 은 여러 파일에서 변수를 공유하는 전역 스코프에 들어감
- 모듈로 만들고 싶은데 `import` / `export` 가 없다면 → `export {}` 한 줄로 강제 가능

```typescript
export {}; // 이 파일을 모듈로 만듦
```

## TS 에서의 모듈

모듈을 다룰 때 신경 써야 할 세 가지:
1. **문법 (Syntax)** — import/export 를 어떻게 쓸까
2. **모듈 해상도 (Module Resolution)** — 모듈 이름과 실제 파일의 매핑
3. **출력 형식 (Module Output Target)** — 어떤 형태의 JS 로 컴파일할까

### ES 모듈 문법

- `export default` — 파일당 하나의 기본 export

```typescript
// @filename: hello.ts
export default function helloWorld() {
  console.log("Hello, world!");
}

// @filename: index.ts
import helloWorld from "./hello.js";
helloWorld();
```

- named export — 여러 개 가능

```typescript
// @filename: maths.ts
export const pi = 3.14;
export function absolute(x: number) { return x < 0 ? x * -1 : x; }

// @filename: app.ts
import { pi, absolute } from "./maths.js";
```

### 추가 import 문법

- `as` 로 이름 바꾸기

```typescript
import { pi as π } from "./maths.js";
```

- default 와 named 를 함께

```typescript
import RandomNumberGenerator, { pi as π } from "./maths.js";
```

- 네임스페이스로 모두 가져오기

```typescript
import * as math from "./maths.js";
math.pi;
math.absolute(-1);
```

- side effect 만을 위해 import

```typescript
import "./side-effect.js";
```

## TS 만의 ES 모듈 문법

### 타입을 값처럼 import/export

- 타입도 값과 같은 문법으로 import 가능

```typescript
// @filename: animal.ts
export type Cat = { breed: string; yearOfBirth: number };
export interface Dog { breeds: string[]; yearOfBirth: number }

// @filename: app.ts
import { Cat, Dog } from "./animal.js";
```

### `import type`

- **타입만** 을 import 하는 명시적 문법
- 런타임에는 완전히 제거됨 → JS 를 다루는 트랜스파일러 (Babel, esbuild, swc) 와의 호환성이 좋음

```typescript
import type { Cat, Dog } from "./animal.js";
type Animals = Cat | Dog;

import type { createCatName } from "./animal.js";
const name = createCatName(); // error: 값으로 사용 불가
```

### 인라인 `type` import (TS 4.5+)

- named import 안에서 개별 항목만 타입으로 표시 가능

```typescript
import { createCatName, type Cat, type Dog } from "./animal.js";
```

- `isolatedModules` 등에서 트랜스파일러가 무엇이 런타임에 남을지 정확히 알 수 있음

## CommonJS 동작을 하는 ES 모듈 문법

- TS 는 CommonJS 와의 상호운용을 위한 특별한 문법을 제공

```typescript
import fs = require("fs");
const code = fs.readFileSync("hello.ts", "utf8");
```

## CommonJS 문법

- Node.js 의 전통적 모듈 시스템
- npm 상당수 패키지가 여전히 CommonJS 로 배포됨

### 내보내기

- `module.exports` 객체에 프로퍼티를 붙임

```typescript
function absolute(num: number) { return num < 0 ? num * -1 : num; }

module.exports = { pi: 3.14, absolute };
```

- 소비하는 쪽에서는 destructuring 으로 가져옴

```typescript
const maths = require("./maths");
maths.pi;

const { pi, absolute } = require("./maths");
```

### ES 모듈과의 상호운용

- CommonJS 와 ES Module 사이에는 default import 취급에 차이가 있음
- TS 는 `esModuleInterop` 플래그로 이 간극을 좁혀줌

## TS 의 모듈 해상도 옵션

- 모듈 이름 → 실제 파일 경로 로 변환하는 방식을 제어

주요 옵션:
- `moduleResolution: "node"` — Node.js 의 CommonJS 방식 시뮬레이션 (전통적 기본값)
- `moduleResolution: "nodenext"` / `"node16"` — 최신 Node.js 의 ESM/CJS 혼용 규칙
- `moduleResolution: "bundler"` (TS 5.0+) — Vite / esbuild / Webpack 등 번들러 환경에 맞춤

## TS 의 모듈 출력 옵션

- 컴파일 결과 JS 가 사용할 모듈 형식을 결정하는 두 옵션
- `target` — 어떤 JS 문법으로 다운레벨링할 것인가 (`ES5`, `ES2015`, `ES2020`, ...)
- `module` — 어떤 모듈 시스템으로 출력할 것인가 (`CommonJS`, `ESNext`, `NodeNext`, ...)

예: `target: ES2020`, `module: NodeNext`

- 모듈 시스템 간의 조합에 따라 출력 코드가 크게 달라짐
- 특히 default import / re-export 부분에서 CommonJS 환경은 헬퍼가 삽입됨

## TS 네임스페이스 (Namespaces)

- ES 모듈 이전의 TS 고유 모듈 시스템
- `namespace` 키워드로 정의 → 내부 스코프를 만들고 이름 충돌을 방지
- 오늘날 새 코드에서는 ES 모듈 사용이 권장됨
- 단, 정말 필요한 경우 (전역 스코프에서 병합, 앰비언트 선언 병합 등) 에는 여전히 유용

```typescript
namespace Utils {
  export function greet(name: string) { return `Hello, ${name}!`; }
}

Utils.greet("world");
```

- 네임스페이스는 별도 문서에서 더 자세히 다룸

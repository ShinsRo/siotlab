# Classes

- TS 는 ES2015 클래스에 완전한 지원을 제공하고, 타입 어노테이션 · 접근 제어자 등 추가 기능을 얹음

## 클래스 멤버 (Class Members)

### 필드 (Fields)

- 필드 선언 → 인스턴스 프로퍼티

```typescript
class Point {
  x: number;
  y: number;
}

const pt = new Point();
pt.x = 0;
pt.y = 0;
```

- 초기값을 주면 타입 추론

```typescript
class Point {
  x = 0;    // number
  y = 0;    // number
}
```

- `strictPropertyInitialization` 옵션이 켜져 있으면, 필드는 **생성자에서 초기화되어야 함**
- 다른 방법으로 확실히 초기화된다고 컴파일러에 알리려면 **확정 할당 단언 연산자 `!`** 사용

```typescript
class OKGreeter {
  name!: string; // 다른 방법으로 초기화됨을 단언
}
```

### `readonly`

- 필드에 `readonly` 를 붙이면 생성자 밖에서 할당 불가

```typescript
class Greeter {
  readonly name: string = "world";

  constructor(otherName?: string) {
    if (otherName !== undefined) this.name = otherName; // OK
  }

  err() { this.name = "not ok"; } // error
}
```

### 생성자 (Constructors)

- 파라미터 어노테이션, 기본값, 오버로드 지원

```typescript
class Point {
  x: number;
  y: number;
  constructor(x = 0, y = 0) {
    this.x = x;
    this.y = y;
  }
}
```

- 함수 시그니처와의 차이
    - 생성자는 타입 파라미터를 가질 수 없음 (클래스 자체가 가짐)
    - 반환 타입 어노테이션 불가 (항상 인스턴스 타입)

### super 호출

- 파생 클래스 생성자 안에서 `this.` 를 사용하려면 먼저 `super()` 호출 필요

```typescript
class Base { k = 4; }
class Derived extends Base {
  constructor() {
    console.log(this.k); // error: super() 호출 전
    super();
  }
}
```

### 메서드 (Methods)

- 클래스 안 함수는 메서드
- 파라미터/반환 타입 어노테이션 사용 가능
- 메서드 안에서 클래스 필드에 접근할 때는 반드시 `this.` 사용

### getter / setter

- `get` / `set` 접근자 지원

```typescript
class C {
  _length = 0;
  get length() { return this._length; }
  set length(value) { this._length = value; }
}
```

- 규칙
    - `get` 만 있으면 자동으로 `readonly`
    - setter 의 파라미터 타입이 없으면 getter 의 반환 타입에서 추론
    - getter/setter 는 같은 멤버 가시성이어야 함
- TS 4.3+ : getter/setter 가 서로 다른 타입을 가질 수 있음 (setter 가 더 관대할 수 있음)

### 인덱스 시그니처

- 객체 타입과 마찬가지로 클래스에도 인덱스 시그니처 사용 가능

```typescript
class MyClass {
  [s: string]: boolean | ((s: string) => boolean);
  check(s: string) { return this[s] as boolean; }
}
```

## 클래스 상속 관계 (Class Heritage)

### `implements` 절

- 인터페이스를 클래스가 만족하는지 검사

```typescript
interface Pingable { ping(): void; }
class Sonar implements Pingable {
  ping() { console.log("ping!"); }
}
```

- **주의**: `implements` 는 클래스 타입을 바꾸지 않고, 검사만 함
    - 인터페이스 프로퍼티가 선택적이면 클래스에서도 선택적이 되지 않음
    - 파라미터 타입을 자동으로 추론해주지 않음

### `extends` 절

```typescript
class Animal { move() { /* ... */ } }
class Dog extends Animal { woof(times: number) { /* ... */ } }
```

#### 메서드 오버라이드

- 파생 클래스가 부모의 메서드를 재정의 가능
- 파생 클래스는 항상 부모 계약을 지켜야 함 (Liskov)

```typescript
class Base {
  greet() { console.log("Hello, world!"); }
}
class Derived extends Base {
  greet(name?: string) {
    if (name === undefined) super.greet();
    else console.log(`Hello, ${name.toUpperCase()}`);
  }
}
```

#### 필드 선언과 초기화 순서

- 부모 → 자식 순서로 초기화
- 자식 필드 초기화가 부모 생성자보다 늦게 실행됨 → 부모 생성자에서 자식이 정의한 값을 사용하려 하면 아직 undefined

```typescript
class Base {
  name = "base";
  constructor() { console.log("My name is " + this.name); }
}
class Derived extends Base {
  name = "derived";
}
new Derived();
// 출력: My name is base
```

- 해결 방법: 필드를 `declare` 로만 선언 (`useDefineForClassFields: true` 환경에서)

#### 내장 타입 상속

- `Error`, `Array` 등 내장 클래스를 상속할 때 ES6 이전 환경에서는 프로토타입 체인이 복원되지 않음
- 생성자 안에서 수동으로 프로토타입 설정 필요

```typescript
class MsgError extends Error {
  constructor(m: string) {
    super(m);
    Object.setPrototypeOf(this, MsgError.prototype);
  }
}
```

## 멤버 가시성 (Member Visibility)

### `public`

- 기본값. 어디서든 접근 가능

### `protected`

- 해당 클래스와 그 하위 클래스에서만 접근 가능

```typescript
class Greeter {
  protected getName() { return "hi"; }
}
class SpecialGreeter extends Greeter {
  howdy() { console.log("Howdy, " + this.getName()); } // OK
}
```

### `private`

- 해당 클래스 내부에서만 접근 가능
- 하위 클래스에서도 접근 불가

```typescript
class Base {
  private x = 0;
}
class Derived extends Base {
  showX() { console.log(this.x); } // error
}
```

- **주의**: TS 의 `private` 는 타입 검사 시점에만 강제. 런타임에는 여전히 접근 가능
- 진짜 런타임 프라이빗을 원하면 JS 의 `#` 프리픽스 사용

```typescript
class Dog { #barkAmount = 0; }
```

## 정적 멤버 (Static Members)

- `static` 키워드로 선언 → 인스턴스가 아닌 클래스 자체에 속함

```typescript
class MyClass {
  static x = 0;
  static printX() { console.log(MyClass.x); }
}
MyClass.printX();
```

- 접근 제어자도 사용 가능
- 예약된 정적 이름 (`name`, `length`, `call`, `prototype` 등) 은 덮어쓸 수 없음

## 클래스에서의 static 블록

- 클래스 자체의 정적 상태를 초기화하는 블록 (`static { ... }`)
- `this` 는 클래스 자신을 참조

## 제네릭 클래스 (Generic Classes)

```typescript
class Box<Type> {
  contents: Type;
  constructor(value: Type) { this.contents = value; }
}
const b = new Box("hello"); // Box<string>
```

- `static` 멤버는 클래스의 타입 파라미터를 참조할 수 없음

## 런타임에서의 `this`

- JS 의 `this` 는 호출 컨텍스트에 따라 결정됨

```typescript
class MyClass {
  name = "MyClass";
  getName() { return this.name; }
}
const c = new MyClass();
const obj = { name: "obj", getName: c.getName };
obj.getName(); // "obj"
```

### 화살표 함수

- 메서드를 화살표 함수 필드로 정의하면 `this` 가 인스턴스로 고정됨
- 단, 인스턴스마다 함수가 새로 생성되어 메모리를 더 씀

```typescript
class MyClass {
  name = "MyClass";
  getName = () => this.name;
}
```

### `this` 파라미터

- 메서드 첫 파라미터로 `this` 를 명시 → 호출 시 `this` 컨텍스트를 컴파일 타임에 검사

```typescript
class MyClass {
  name = "MyClass";
  getName(this: MyClass) { return this.name; }
}
```

- `this` 파라미터는 JS 에는 실제로 존재하지 않음 → 컴파일 시 제거됨

## `this` 타입

- 클래스에서 `this` 는 특별한 타입 → 현재 클래스의 타입을 동적으로 참조

```typescript
class Box {
  contents = "";
  set(value: string): this {
    this.contents = value;
    return this;
  }
}

class ClearableBox extends Box {
  clear() { this.contents = ""; }
}

const a = new ClearableBox().set("hi"); // ClearableBox (this 타입 덕분)
```

- 파라미터 타입으로도 사용 가능 → `this is Type` 형태의 타입 가드도 정의 가능

## 파라미터 프로퍼티 (Parameter Properties)

- 생성자 파라미터 앞에 접근 제어자 → 자동으로 필드 선언 + 할당

```typescript
class Params {
  constructor(
    public readonly x: number,
    protected y: number,
    private z: number
  ) {}
}
const a = new Params(1, 2, 3);
console.log(a.x); // OK
```

## 클래스 표현식 (Class Expressions)

- 이름이 없는 클래스를 표현식으로 사용 가능

```typescript
const someClass = class<Type> {
  content: Type;
  constructor(value: Type) { this.content = value; }
};

const m = new someClass("Hello, world"); // someClass<string>
```

## 생성자 시그니처

- 클래스는 값이자 타입 → `typeof` 로 생성자 타입을 얻어 사용

```typescript
class Point {
  createdAt: number;
  x: number;
  y: number;
  constructor(x: number, y: number) {
    this.createdAt = Date.now();
    this.x = x;
    this.y = y;
  }
}
type PointInstance = InstanceType<typeof Point>;
function moveRight(p: PointInstance) { p.x += 5; }
```

## `abstract` 클래스와 멤버

- 추상 클래스는 직접 인스턴스화 불가 → 상속받아 구현체를 만들어야 함
- 추상 메서드/필드는 하위 클래스에서 반드시 구현되어야 함

```typescript
abstract class Base {
  abstract getName(): string;
  printName() { console.log("Hello, " + this.getName()); }
}
class Derived extends Base {
  getName() { return "world"; }
}
```

### 추상 생성 시그니처

- 추상 클래스를 생성하는 함수를 표현할 때 `abstract new (...)` 형태의 시그니처 필요

```typescript
function greet(ctor: new () => Base) { /* 일반 클래스만 받음 */ }
function greetAbstract(ctor: abstract new () => Base) { /* 추상 클래스도 받음 */ }
```

## 클래스 사이의 관계

- TS 는 **구조적 (structural) 타입 시스템** → 클래스 관계도 이름이 아니라 구조로 판단

```typescript
class Point1 { x = 0; y = 0; }
class Point2 { x = 0; y = 0; }

const p: Point1 = new Point2(); // OK, 구조가 같음
```

- 서로 다른 이름의 클래스도 같은 구조면 호환됨
- 반대로 완전히 빈 클래스는 어떤 것과도 호환됨 → 브랜딩 없이는 강제할 방법이 없음

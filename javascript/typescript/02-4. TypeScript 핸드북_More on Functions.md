# More on Functions

## 함수 타입 표현식 (Function Type Expressions)

- 함수를 값으로 다룰 때, 가장 간단한 방법은 함수 타입 표현식
- 화살표 함수와 문법이 유사함 `(파라미터: 타입) => 반환타입`

```typescript
function greeter(fn: (a: string) => void) {
  fn("Hello, World");
}

function printToConsole(s: string) {
  console.log(s);
}

greeter(printToConsole);
```

- 파라미터 이름은 **필수** (`(string) => void` 는 `string` 이라는 이름의 `any` 파라미터로 해석됨)
- 타입 별칭 (type alias) 으로 이름을 붙일 수 있음

```typescript
type GreetFunction = (a: string) => void;
function greeter(fn: GreetFunction) { /* ... */ }
```

## 호출 시그니처 (Call Signatures)

- 함수는 호출 가능한 것 외에도 프로퍼티를 가질 수 있음
- 함수 타입 표현식으로는 프로퍼티 선언이 불가 → 객체 타입에 **호출 시그니처** 로 표현

```typescript
type DescribableFunction = {
  description: string;
  (someArg: number): boolean;
};

function doSomething(fn: DescribableFunction) {
  console.log(fn.description + " returned " + fn(6));
}
```

- 함수 타입 표현식과 달리 `=>` 가 아닌 `:` 로 반환 타입을 구분

## 생성자 시그니처 (Construct Signatures)

- `new` 로 호출 가능한 "생성자" 함수 타입 표현
- 호출 시그니처 앞에 `new` 키워드 추가

```typescript
type SomeConstructor = {
  new (s: string): SomeObject;
};

function fn(ctor: SomeConstructor) {
  return new ctor("hello");
}
```

- `Date` 처럼 `new` 없이도 호출 가능한 경우 → 호출/생성 시그니처를 함께 선언

```typescript
interface CallOrConstruct {
  (n?: number): string;
  new (s: string): Date;
}
```

## 제네릭 함수 (Generic Functions)

- 입력 타입과 출력 타입이 연관될 때 → 타입 파라미터로 관계를 표현

```typescript
function firstElement<Type>(arr: Type[]): Type | undefined {
  return arr[0];
}

const s = firstElement(["a", "b", "c"]); // s: string
const n = firstElement([1, 2, 3]);       // n: number
```

### 추론 (Inference)

- 호출 시 타입 인자를 직접 명시하지 않아도, TS 가 컨텍스트로부터 추론함

```typescript
function map<Input, Output>(arr: Input[], func: (arg: Input) => Output): Output[] {
  return arr.map(func);
}

const parsed = map(["1", "2", "3"], (n) => parseInt(n));
// Input=string, Output=number 로 자동 추론
```

### 제약 (Constraints)

- 타입 파라미터가 만족해야 할 조건을 `extends` 로 지정

```typescript
function longest<Type extends { length: number }>(a: Type, b: Type): Type {
  return a.length >= b.length ? a : b;
}

const longerArray = longest([1, 2], [1, 2, 3]); // number[]
const longerString = longest("alice", "bob");    // "alice" | "bob"
longest(10, 100); // error: number 는 length 속성이 없음
```

### 제약된 값과 작업 (Working with Constrained Values)

- 흔한 실수: 제약을 걸었지만 반환 타입이 실제 인자와 다를 수 있음

```typescript
function minimumLength<Type extends { length: number }>(
  obj: Type, minimum: number
): Type {
  if (obj.length >= minimum) return obj;
  return { length: minimum }; // error: Type 이 아닌 다른 객체
}
```

- 제네릭은 "인자로 전달된 그 타입 그대로" 반환해야 함

### 타입 인자 명시 (Specifying Type Arguments)

- 추론이 실패하거나 원하는 결과가 아닐 때 직접 지정

```typescript
function combine<Type>(arr1: Type[], arr2: Type[]): Type[] {
  return arr1.concat(arr2);
}

combine([1, 2, 3], ["hello"]);           // error
combine<string | number>([1, 2, 3], ["hello"]); // OK
```

### 좋은 제네릭 함수 작성 지침

- **타입 파라미터를 아래로 내려라 (Push Type Parameters Down)**
    - 필요 이상으로 제약하지 말 것
- **타입 파라미터를 적게 써라 (Use Fewer Type Parameters)**
    - 관계를 표현하지 않는 파라미터는 제거
- **타입 파라미터는 두 번 이상 등장해야 한다 (Type Parameters Should Appear Twice)**
    - 한 번만 쓰이면 그건 관계가 아니라 그냥 `any` 와 다를 바 없음

```typescript
// bad
function greet<Str extends string>(s: Str) { console.log("Hello, " + s); }
// good
function greet(s: string) { console.log("Hello, " + s); }
```

## 선택적 파라미터 (Optional Parameters)

- 이름 뒤 `?` → 선택적, 타입은 `T | undefined`
- 기본값을 주면 호출 시 생략 시 그 값이 사용됨

```typescript
function f(x?: number) { /* x: number | undefined */ }
function g(x = 10) { /* x: number */ }
```

### 콜백에서의 선택적 파라미터

- **콜백을 정의할 때 선택적 파라미터 사용 지양**
- 호출자가 항상 인자를 다 넘길 수 있는데, 콜백 시그니처는 그것을 반영하지 않으면 혼란만 생김

```typescript
function myForEach(arr: any[], callback: (arg: any, index?: number) => void) {
  for (let i = 0; i < arr.length; i++) callback(arr[i], i);
}

// 사용자가 index 를 쓰면 index?: number 이므로 undefined 로 나타남 → 불편
```

- 원칙: **파라미터를 적게 받는 함수는 항상 파라미터를 더 받는 함수에 대입 가능함**

## 함수 오버로드 (Function Overloads)

- 인자 개수 / 타입에 따라 다른 시그니처를 갖는 함수 표현
- 여러 개의 **오버로드 시그니처** + 하나의 **구현 시그니처** 로 구성

```typescript
function makeDate(timestamp: number): Date;
function makeDate(m: number, d: number, y: number): Date;
function makeDate(mOrTimestamp: number, d?: number, y?: number): Date {
  if (d !== undefined && y !== undefined) {
    return new Date(y, mOrTimestamp, d);
  }
  return new Date(mOrTimestamp);
}

makeDate(12345678);       // OK
makeDate(5, 5, 5);        // OK
makeDate(1, 3);           // error: 매칭되는 오버로드 없음
```

- **구현 시그니처는 외부에서 볼 수 없음** → 오버로드 시그니처만 호출 가능

### 좋은 오버로드 작성

- 가능하면 **유니언 타입 파라미터** 로 대체
- 오버로드를 쓰기 전에 자문할 것 → "이걸 유니언으로 표현할 수 없을까?"

```typescript
// bad
function len(s: string): number;
function len(arr: any[]): number;
function len(x: any) { return x.length; }

// good
function len(x: string | any[]): number { return x.length; }
```

### `this` 선언

- 첫 파라미터로 `this` 를 선언하면 함수 안에서 `this` 의 타입이 명확해짐 (JS 에는 없는 TS 문법)

```typescript
interface DB {
  filterUsers(filter: (this: User) => boolean): User[];
}

const admins = db.filterUsers(function (this: User) {
  return this.admin;
});
```

- 화살표 함수는 자신의 `this` 를 가지지 않으므로 이런 경우엔 `function` 문법 사용

## 알아둘 다른 타입들

### `void`

- 값을 반환하지 않는 함수의 반환 타입
- JS 의 `undefined` 와 **동일하지 않음**
- `void` 반환 타입은 다른 반환값을 무시하게 해줌 → 콜백에서 유용

```typescript
type voidFunc = () => void;
const f: voidFunc = () => { return true; }; // OK, 반환값 무시됨
const v = f(); // v: void
```

### `object`

- 원시 타입 (string, number, bigint, boolean, symbol, null, undefined) 이 **아닌** 모든 값
- `Object` (대문자) 나 `{}` 와는 다름
- 함수는 `object` 임 (JS 에선 함수도 객체)

### `unknown`

- `any` 와 비슷하게 **어떤 값이든** 담을 수 있음
- 하지만 사용하려면 좁혀야 함 → 더 안전
- API 경계에서 `any` 대신 쓰는 것이 권장됨

```typescript
function safeParse(s: string): unknown { return JSON.parse(s); }
const obj = safeParse(someRandomString);
// obj 를 바로 사용할 수 없음 → 좁혀야 함
```

### `never`

- **절대 발생하지 않는** 값 (예외, 무한 루프)
- 유니언에서 모든 케이스를 소진한 후 남는 타입 → 완전성 검사에 사용
- 모든 타입에 할당 가능하지만, 어떤 것도 `never` 에 할당 불가

### `Function`

- 대문자 `Function` — 모든 함수 값이 가진 공통 타입
- `bind`, `call`, `apply` 등이 있음
- 호출하면 반환 타입이 `any` → 안전하지 않음, 되도록 피할 것
- 익명 함수 타입 `() => void` 를 대신 사용

## 나머지 파라미터/인자 (Rest Parameters and Arguments)

### 나머지 파라미터 (Rest Parameters)

- 가변 개수의 인자를 받을 때 `...args` 문법 사용
- 타입은 배열 형태 (`T[]` 또는 튜플)

```typescript
function multiply(n: number, ...m: number[]) {
  return m.map((x) => n * x);
}

const a = multiply(10, 1, 2, 3, 4); // [10, 20, 30, 40]
```

### 나머지 인자 (Rest Arguments)

- 반대로, 배열을 함수 호출 시 개별 인자로 펼쳐 넘기는 것 (`...`)
- TS 는 배열이 **불변** 이라 가정하지 않음 → 종종 `as const` 필요

```typescript
const args = [8, 5] as const;
const angle = Math.atan2(...args); // OK
```

## 파라미터 구조 분해 (Parameter Destructuring)

- 객체를 인자로 받아 여러 변수로 분해할 때, 타입도 함께 표현 가능

```typescript
function sum({ a, b, c }: { a: number; b: number; c: number }) {
  console.log(a + b + c);
}

// 타입 별칭 사용
type ABC = { a: number; b: number; c: number };
function sum2({ a, b, c }: ABC) { /* ... */ }
```

## 함수의 할당 가능성 (Assignability of Functions)

### 반환 타입이 `void` 인 경우

- 반환 타입이 `void` 인 함수 타입에는 **어떤 값이든 반환하는 함수** 를 할당해도 됨
- 단, 반환값은 무시됨

```typescript
type voidFunc = () => void;

const f1: voidFunc = () => true;
const f2: voidFunc = () => "hello";

// 다만, 함수 선언문 (function declaration) 은 반환 타입 void 를 그대로 지킴
function f3(): void {
  return true; // error
}
```

- 이 특성이 있어 `Array.prototype.push` (반환값 number) 를 `forEach` 콜백처럼 `void` 콜백에 넘길 수 있음

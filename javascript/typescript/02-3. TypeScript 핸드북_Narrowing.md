# Narrowing

## `typeof` type guards

- `typeof` 는 런타임에서 기초적인 타입 정보를 줌
    - "string"
    - "number"
    - "bigint"
    - "boolean"
    - "symbol"
    - "undefined"
    - "object"
    - "function"
- typeof null 이 "object" 이라던지, if 컨디션에서 값이 true/false 로 변환된다던지의 JS 특성에 유의할 것

## 평등 축소

- if, switch 와 같은 동등성 감사로 축소 가능
- JS 의 느슨한 동등성 검사로도 축소 가능 (==, !=)

```typescript
function example(x: string | number, y: string | boolean) {
  if (x === y) {
    // We can now call any 'string' method on 'x' or 'y'.
    x.toUpperCase();
    y.toLowerCase();
  } else {
    console.log(x);
    console.log(y);
  }
}
```

```typescript
interface Container {
  value: number | null | undefined;
}
 
function multiplyValue(container: Container, factor: number) {
  // Remove both 'null' and 'undefined' from the type.
  if (container.value != null) {
    console.log(container.value); // (property) Container.value: number

    // Now we can safely multiply 'container.value'.
    container.value *= factor;
  }
}
```

## `in` 연산자 축소

- JS 에서 객체 또는 프로토타입 체인에 특정 이름 속성이 있는지 확인하는 연산자 `in`
- 이를 통해 잠재적 타입을 좁힐 수 있음

```typescript
type Fish = { swim: () => void };
type Bird = { fly: () => void };
type Human = { swim?: () => void; fly?: () => void };
 
function move(animal: Fish | Bird | Human) {
  if ("swim" in animal) {
    animal; // (parameter) animal: Fish | Human
  } else {
    animal; // (parameter) animal: Bird | Human
  }
}
```

## `instanceof` 축소

- JS 에서 `x instnaceof Foo` 는`x` 의 프로토타입 체인에 `Foo.prototype` 이 포함되어 있는지 확인
- `new` 키워드로 생성할 있있 는  대부분의 값에 유용하게 사용할 수 있음

## 할당

```typescript
let x = Math.random() < 0.5 ? 10 : "hello world!"; // let x: string | number

x = 1;
console.log(x); // let x: number

x = "goodbye!";
console.log(x); // let x: string

x = true; // error. 선언에 미포함된 타입
```

## 제어 흐름 분석

- 지금까지의 예시들은 TS 가 특정 분기 안에서 어떻게 타입을 좁히는지 보여줬음
- 하지만 실제로는 그보다 더 많은 일이 일어남 → **제어 흐름 분석 (control flow analysis)**
- 코드의 도달 가능성 (reachability) 을 따라가며, 각 지점에서 변수의 타입이 무엇인지 계속 추적함

```typescript
function example() {
  let x: string | number | boolean;

  x = Math.random() < 0.5;
  console.log(x); // let x: boolean

  if (Math.random() < 0.5) {
    x = "hello";
    console.log(x); // let x: string
  } else {
    x = 100;
    console.log(x); // let x: number
  }

  return x; // let x: string | number
}
```

- 분기 안에서 재할당 → 그 지점 이후 타입이 재조정됨
- 분기 이후 합쳐진 지점에서는 각 분기 결과의 유니언으로 결정됨

## 타입 술어 (Type predicates) 사용

- `typeof`, `instanceof` 처럼 내장 기법으로 안 되는 사용자 정의 축소가 필요한 경우
- 반환 타입이 `parameterName is Type` 형태인 함수를 정의 → **타입 술어 (type predicate)**

```typescript
function isFish(pet: Fish | Bird): pet is Fish {
  return (pet as Fish).swim !== undefined;
}

let pet = getSmallPet();

if (isFish(pet)) {
  pet.swim(); // pet: Fish
} else {
  pet.fly();  // pet: Bird
}
```

- `isFish` 가 `true` 를 반환 → `pet` 은 `Fish` 로 축소
- `false` → `Bird` 로 축소 (else 브랜치에서)
- 배열 필터링 등에서도 활용 가능

```typescript
const zoo: (Fish | Bird)[] = [getSmallPet(), getSmallPet(), getSmallPet()];
const underWater: Fish[] = zoo.filter(isFish);
```

### 단언 함수 (Assertion functions)

- 반환하는 대신 조건이 만족되지 않으면 **예외를 던지는** 함수
- 이후 코드에서 특정 타입임을 보장할 수 있음
- 반환 타입에 `asserts` 키워드 사용

```typescript
function assertIsString(val: any): asserts val is string {
  if (typeof val !== "string") {
    throw new Error("Not a string!");
  }
}

function example(val: string | number) {
  assertIsString(val);
  console.log(val.toUpperCase()); // val: string
}
```

## 구별된 유니온 (Discriminated unions)

- 지금까지의 예제는 대개 하나의 변수, 단순 타입을 다뤘음
- 실제로는 유니온의 각 멤버가 공통 리터럴 속성으로 구분되는 경우가 많음

```typescript
interface Shape {
  kind: "circle" | "square";
  radius?: number;
  sideLength?: number;
}

function getArea(shape: Shape) {
  return Math.PI * shape.radius ** 2;
  // error: 'shape.radius' is possibly 'undefined'
}
```

- 위 방식은 optional 필드로 표현 → 실제로 `kind` 가 `"circle"` 인지 확인해도 `radius` 가 있음을 보장하지 못함
- 해결책: 각 케이스를 별도 타입으로 나누고, `kind` 를 **판별자 (discriminant)** 로 사용

```typescript
interface Circle {
  kind: "circle";
  radius: number;
}

interface Square {
  kind: "square";
  sideLength: number;
}

type Shape = Circle | Square;

function getArea(shape: Shape) {
  if (shape.kind === "circle") {
    return Math.PI * shape.radius ** 2; // shape: Circle
  }
}
```

- `kind` 가 리터럴 타입 → TS 가 자동으로 어느 멤버인지 판별해 축소해줌
- `switch` 문에서 특히 강력하게 동작

```typescript
function getArea(shape: Shape) {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;   // shape: Circle
    case "square":
      return shape.sideLength ** 2;         // shape: Square
  }
}
```

- 메시지 전송, 상태 관리, 리덕서 등 다양한 곳에서 유용
- 특히 네트워크 통신 (client/server) 이나 상태 프레임워크에서 필수적인 패턴

## `never` 타입

- 축소를 반복하다 보면 모든 가능성이 소진되어 아무 타입도 남지 않는 상황이 발생함
- 이때 TS 는 `never` 타입을 사용해 "존재해서는 안 되는 상태" 를 표현
- `never` 는 모든 타입에 할당 가능하지만, `never` 자체 외의 어떤 타입도 `never` 에 할당 불가

## 완전성 검사 (Exhaustiveness checking)

- `never` 타입을 활용하면 유니온의 모든 경우를 처리했는지 컴파일 타임에 검사할 수 있음
- 처리하지 못한 케이스가 있으면 컴파일 에러가 나도록 강제

```typescript
type Shape = Circle | Square;

function getArea(shape: Shape) {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "square":
      return shape.sideLength ** 2;
    default:
      const _exhaustive: never = shape;
      return _exhaustive;
  }
}
```

- 새로운 케이스 (예: `Triangle`) 를 유니온에 추가하면 → `default` 브랜치에서 `never` 할당이 실패 → 컴파일 에러
- 유니온이 확장될 때 모든 처리 지점을 강제로 업데이트하게 만드는 유용한 패턴

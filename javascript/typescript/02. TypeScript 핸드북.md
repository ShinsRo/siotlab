# The Basics

- JavaScript 와 딜리
    - 타입스크립트는 정적 타입 검사기를 가짐
    - 호출할 수 없는 것에 대한 호출이 오류를 반환함
    - ex. 연산자 적용 불가, 논리 오류, 오타 등
- 정적 타입 검사에 따른 도구 지원 가능
    - ex. 타입 체커, 자동 완성, 오류 표시 등의 툴링 

## `tsc`: 타입스크립트 컴파일러

- 다음과 같이 전역 설치: `npm install -g typescript`
- 다음과 같이 타입 검사: `tsc hello.ts`
    - `hello.js` 라는 파일이 출력 됌
    - 오류가 존재할 경우 명령줄 상 오류 확인 가능
- `--noEmitOnError` 와 같은 플래그를 통해 오류 시 소스 맵 등 컴파일러 출력 파일 생성 제한 가능


## 명시적 유형

```typescript
function greet(person: string, date: Date) {
  console.log(`Hello ${person}, today is ${date.toDateString()}!`);
}
```

다음과 같은 오류를 방지 할 수 있음

```typescript
function greet(person: string, date: Date) {
  console.log(`Hello ${person}, today is ${date.toDateString()}!`);
}
 
greet("Maddison", Date());
// Argument of type 'string' is not assignable to parameter of type 'Date'.
// JavaScript 에서 Date() 콜은 string 을 반환하기 때문
// greet("Maddison", new Date()); 으로 수정.
```

- 암시적 타입 추론이 쓰일 수 있음
- 타입 어노테이션은 프로그램의 런타임 동작을 변경하지 않음

## 다운 레벨링

위의 템플릿 문자열은 다음과 같이 재작성 됨

```javascript
"Hello ".concat(person, ", today is ").concat(date.toDateString(), "!");
```

- 템플릿 문자열은 ES6 의 사양: 위는 ES3, ES5 로 재작성된 결과
- 타입스크립트는 ES5 가 대상. `--target es2015` 등으로 버전 특정 가능

## Strictness

- 타입스크립트에서 타입은 선택사항
- 타입 추론은 가장 관대한 타입을 사용함: 잠재적 `null` / `undefined` 값에 대해 체크하지 않음
- strictness 설정을 통해 조절 가능; 예를 들어
    - CLI 에서의 strict 플래그
    - `tsconfig.json` 에서의 `"strict": true`
- 대표적인 옵션
    - `noImplicitAny`
        - 암묵적 `any` 타입으로 추론될 때 오류를 발생시킴
    - `strictNullChecks`
        - 일반적으로 `null` 과 `undefined` 는 어느 타입에도 대입 가능
        - `null`, `undefined` 핸들링 누락을 방지

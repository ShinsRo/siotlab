# Everyday Types

## Primitives: `string`, `number` 그리고 `boolean`

- JS 에 대응하는 3가지 원시 타입
- `typeof` 연산자를 사용했을 때 얻을 수 있는 것과 동일

## 배열

- `number[]` = `Array<number>`

## `any`

- `any` 타입 값에 대해 임의의 속성에 접근 가능 (이떄 반환 값은 `any`)
- 호출, 할당 등 구문적 유효한 것이라면 무엇이든 가능
- 타입이 지정되지 않은 값에 대해 타입 추론이 불가하면 컴파일러는 `any` 타입을 부여하는 것이 기본 동작

```typescript
let obj: any = { x: 0 };
// 아래 이어지는 코드들은 모두 오류 없이 정상적으로 실행됩니다.
// `any`를 사용하면 추가적인 타입 검사가 비활성화되며,
// 당신이 TypeScript보다 상황을 더 잘 이해하고 있다고 가정합니다.
obj.foo();
obj();
obj.bar = 100;
obj = "hello";
const n: number = obj;
```

## 변수 타입 표기

- `const`, `var` 혹은 `let` 등을 사용하여 변수 선언 시 타입 표기 가능
- ex. `let myName: string = "Alice";`
- 표기하지 않을 시 타입을 자동 추론 - 추론 규칙을 학습할 필요는 없음

## 함수

- 매개변수 타입 표기: ex. `function greet(name: string) { ... }`
- 반환 타입 표기: ex. `function getValue(): number { return 26; }`
- 익명 함수의 매개 변수 타입 추론은 호출부를 알 수 있다면 추론 가능 (람다식도 마찬가지. 문맥적 타입 부여)

## 객체 타입

```typescript
// 매개 변수의 타입은 객체로 표기되고 있습니다.
function printCoord(pt: { x: number; y?: number }) {
  console.log("The coordinate's x value is " + pt.x);
  console.log("The coordinate's y value is " + pt.y);
}
printCoord({ x: 3, y: 7 });
```

- 객체 타입: 프로퍼티를 갖는 JS 값
- 위의 객체 타입 매개 변수에서 각 프로퍼티 타입 표기는 선택사항 (미표기 시 `any`)
- 위의 객체 타입 매개 변수에서 y 는 `?` 가 붙어 옵셔널 프로퍼티
- 옵셔널 프로퍼티를 사용할 때, `undefined` 여부 확인이 필요

## 유니언 타입

```typescript
function printId(id: number | string) {
  console.log("Your ID is: " + id);
}
// OK
printId(101);
// OK
printId("202");
// 오류
printId({ myID: 22342 });
```

- 서로 다른 두 개 이상의 타입을 사용하여 만듦
- 각 타입 중 하르를  나타입으로 가질 수 있음 
- 조합에 사용된 각 타입을 유니언 타입의 멤버라 부름
- 유니언 다룰 시 멤버 모두에 유효한 작업(ex. 메서드 호출)일 때 사용 가능
- Narrowing 을 통해 (ex. `if(typeof id === "string") ...`) 개별멤버 사용 가능
- 공통 내장 메서드가 있다면 좁히기 없이도 사용 가능

## 타입 별칭

```typescript
type Point = {
  x: number;
  y: number;
};
 
// 앞서 사용한 예제와 동일한 코드입니다
function printCoord(pt: Point) {
  console.log("The coordinate's x value is " + pt.x);
  console.log("The coordinate's y value is " + pt.y);
}
 
printCoord({ x: 100, y: 100 });

type ID = number | string;
```

- 타입 별칭은 별칭일 뿐: 동일 타입에 대한 구분된 버전이 아님

## 인터페이스

```typescript
interface Point {
  x: number;
  y: number;
}
 
function printCoord(pt: Point) {
  console.log("The coordinate's x value is " + pt.x);
  console.log("The coordinate's y value is " + pt.y);
}
 
printCoord({ x: 100, y: 100 });
```

## 타입 별칠 vs 인터페이스

- 타입 별칭은 새 프로퍼티 추가에 대해 열려있지 않음
- 인터페이스는 항상 확장할 수 있음
- 잘 모르겠다면, 우선 interface를 사용하고 이후 문제가 발생하였을 때 type을 사용

```typescript
// 인터페이스 확장
interface Animal {
  name: string
}

interface Bear extends Animal {
  honey: boolean
}
```
```typescript
// 교집합을 통한 확장
type Animal = {
  name: string
}

type Bear = Animal & {
  honey: Boolean
}
```
```typescript
const bear = getBear()
bear.name
bear.honey
```

```typescript
// 기존 인터페이스에 새 필드를 추가
interface Window {
  title: string
}

interface Window {
  ts: TypeScriptAPI
}

const src = 'const a = "Hello World"';
window.ts.transpileModule(src, {});

// 타입 별칭은 생성된 뒤 달라질 수 없음
```

## 타입 단언

- ex. `const myCanvas = document.getElementById("main_canvas") as HTMLCanvasElement;`
- 상동. `const myCanvas = <HTMLCanvasElement>document.getElementById("main_canvas");` (코드가 .tsx 파일이 아닌경우)
- 타입 표기와 마찬가지로 타입 단언은 컴파일러ㄹ에 의하여 제거, 런타임 동작에는 미영향
- 더 구체적이거나 덜 구체적인 타입 단언만 허용 (invariant 하면 안된다는 말임)
    - 이걸 회피할 순 있음: `const a = (expr as any) as T;`

## 리터럴 타입

- `const a = "Hello World"` 이면 `const a: "Hello World"`
- 유니언과 함께 사용하여 다양한 개념 표현 가능

```typescript
function printText(s: string, alignment: "left" | "right" | "center") { ... }
function compare(a: string, b: string): -1 | 0 | 1 { ... }
function configure(x: Options | "auto") { ... }
```

- 불 리터럴 타입 `true`, `false` 도 존재함

### 리터럴 추론

객체를 사용하여 변수 초기화 시, TS 는 그 값이 변화할 수 있다고 가정함

```typescript
const obj = { counter: 0 };
if (someCondition) {
  // 오류가 아님. 다시 말해 obj.counter 는 반드시 number 여야 함
  // 타입이 읽기 및 쓰기 두 동작을 결정하는 데에 사용되기 때문
  obj.counter = 1; 
}

const req = { url: "https://example.com", method: "GET" };
handleRequest(req.url, req.method); // 오류
// req.method 는 string 으로 추론됨
```

```typescript
// 수정 1-1: `req.method` 가 항상 리터럴 타입 "GET" 이길 의도
const req = { url: "https://example.com", method: "GET" as "GET" };
// 수정 1-2: `req.method` 가 항상 "GET" 이다라고 선언
handleRequest(req.url, req.method as "GET");
```

```typescript
// 수정 2: `as const` 로 설정
const req = { url: "https://example.com", method: "GET" } as const;
handleRequest(req.url, req.method);
```

## `null` 과 `undefined`

- 빈 값 또는 초기화되지 않은 값을 가르키는 두 가지 원시값
- `strictNullChecks` 옵션 설정에 따라 달라짐
    - 미설정 시 어떤 값이 `null` or `undefined` 일 수 있더라도, 값에 접근 가능
        - 모든 타입 변수에 대입 될 수 있음
        - 설정하는 것이 권장사항
    - 설정 시 프로퍼티 사용 전 해당 값을 테스트해야함 - Narrowing
- Null 아님 단언 연산자 `!` 접미사 존재

```typescript
function liveDangerously(x?: number | undefined) {
  // 오류 없음
  console.log(x!.toFixed());
}
```

## 자주 사용되지 않는 원시형 타입

- `bigint`: 큰 정수
- `symbol`: 전역적으로 고유한 참조값을 생성하는 데에 사용할 수 있는 원시 타입
